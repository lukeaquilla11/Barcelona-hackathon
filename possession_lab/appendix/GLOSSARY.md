# Possession Lab Glossary

Short definitions for the terms we use in this project.

## The data and task

**Frame**  
One image/time point from the video. This match has 25 frames per second.

**Video frame index**  
The row number used in our submission, from `0` to `199318`.

**ATD**  
Automatic Tracking Data. It contains detected player and ball locations over time. It is not the
answer key; it is an input signal.

**Homography**  
A mathematical mapping between the camera image and the football pitch. It helps convert image
positions into pitch positions, or project pitch positions back onto the image.

**Smart Tagging**  
Automatic labels for phases and set pieces, such as kick-offs or build-up phases. It is useful
context, but it is not possession ground truth.

**Feature**  
A piece of information given to a model. Examples: ball position, nearest player distance, number
of visible players, ball speed, or whether the camera geometry is valid.

**Target / label**  
The answer the model should produce. Here the labels are `H`, `A`, `D`, or `X`.

**Occlusion**  
When the ball or a player is hidden, unclear, or not detected. A missing ball is not automatically
`X`; the model should infer the state from context.

**Dead ball (`D`)**  
The ball is not actively in play: for example, during a stoppage, restart, or other dead-ball
period.

**Possession spell**  
A continuous interval where the same team has the ball alive. Example: frames 500–720 labelled
`H` form one home possession spell.

## Time and prediction

**Time series**  
Data ordered in time. Tracking data is a time series because each frame follows the previous one.

**Sequence labelling**  
Assigning a label to every item in a sequence. Here, we assign `H`, `A`, or `D` to every relevant
video frame.

**Forecasting**  
Predicting a future value using the past. We do not have to do pure forecasting: this competition
is mainly sequence labelling, and we can use nearby future frames during offline smoothing.

**Temporal context**  
Information from nearby frames. If the ball disappears for five frames but the same player/team is
clearly in possession before and after, temporal context helps bridge the gap.

**Temporal smoothing**  
Reducing frame-to-frame noise by considering neighbouring predictions. For example:

```text
raw:      H H A H H H A A
smoothed: H H H H H H A A
```

It should remove implausible flicker without erasing real possession changes.

**Rolling window**  
A moving group of nearby frames used to calculate a feature or decision, such as the average ball
speed over the previous 10 frames.

**Transition**  
The point where the state changes, such as `H → A` or `D → H`.

**State**  
The current condition of the match at a frame: `H`, `A`, or `D`.

**State machine**  
Code that controls which state changes are plausible. For example, it can discourage a one-frame
`H → A → H` flicker unless the evidence is strong.

**HMM (Hidden Markov Model)**  
A probabilistic state machine. It combines evidence for the current frame with probabilities of
staying in or switching between states.

**CRF (Conditional Random Field)**  
A model that predicts a whole sequence while encouraging compatible neighbouring labels. It is
another way to model sequence structure.

**Temporal CNN / LSTM / Transformer**  
Neural-network approaches that learn patterns across multiple time steps rather than looking at
one frame independently.

**Fragmentation**  
Breaking one real possession into many short predicted spells because of flickering labels. This
can hurt `spellF1` even when frame-level accuracy looks reasonable.

## Learning approaches

**Supervised learning**  
Learning from examples with known answers. For this competition, labelled training matches must be
other matches, not this provided match.

**Unsupervised learning**  
Finding structure without answer labels, such as clustering similar movement patterns. It does not
automatically know which cluster means `H`, `A`, or `D`.

**Semi-supervised learning**  
Using a smaller labelled dataset together with a larger unlabelled dataset. The labelled matches
must still be different from the competition match.

**Self-supervised learning**  
Creating a learning task from the input itself, such as hiding some tracking values and asking the
model to reconstruct them. Teacher–student training is one possible self-supervised technique, but
self-supervised learning is a wider category.

**Pseudo-label**  
A label generated by an algorithm rather than a person. Pseudo-labels can be useful, but manually
correcting them on this match would violate the competition rules.

**Inference**  
Running a trained or designed model to produce predictions on new data.

**Training**  
Adjusting model parameters using examples so the model learns a pattern.

**Validation**  
Checking or comparing approaches while developing. For this challenge, do not use the public
five-minute labels as a tuning/validation set; use other matches or legal unsupervised checks.

**Test set**  
Data reserved for the final evaluation. The provided full match is effectively the test match, and
its full ground truth is private.

**Generalisation**  
Performing well on a new match rather than memorising the training matches.

**Data leakage**  
Accidentally giving the model information that would not be available at prediction time, such as
private labels or human annotations from the competition match.

**Baseline**  
A simple reference method. It gives us something to beat and helps verify that the pipeline works.

## Metrics

**True positive (TP)**  
The model predicted a class and was correct. Example: the frame was truly `H` and we predicted `H`.

**False positive (FP)**  
The model predicted a class when it was wrong. Example: we predicted `H`, but the frame was `A`.

**False negative (FN)**  
The model failed to predict a class that was truly present. Example: the frame was `H`, but we
predicted `A`, `D`, or `X`.

**Precision**  
Of the frames predicted as a class, how many were correct?

```text
precision = TP / (TP + FP)
```

**Recall**  
Of the frames truly belonging to a class, how many did we find?

```text
recall = TP / (TP + FN)
```

**F1 score**  
The harmonic mean of precision and recall. It is high only when both are high.

```text
F1 = 2 × precision × recall / (precision + recall)
```

**Macro-F1**  
Calculate F1 separately for `H`, `A`, and `D`, then average them equally. It is the frame-level
summary metric and a leaderboard tie-break.

**IoU (Intersection over Union)**  
How much two time intervals overlap compared with their combined extent.

```text
IoU = overlap duration / union duration
```

If the true spell is frames 10–20 and our spell is 15–25, the overlap is 5 frames and the union is
15 frames, so IoU is `5/15 = 0.333`.

**Spell precision**  
The proportion of predicted possession spells that match a real same-team spell sufficiently well.

**Spell recall**  
The proportion of real possession spells that our model finds sufficiently well.

**SpellF1**  
F1 applied to possession spells rather than individual frames. The scorer performs one-to-one
matching at IoU thresholds `0.3, 0.4, 0.5, 0.6, 0.7` and averages the resulting F1 scores. This is
the main ranking metric.

**Latency**  
How early or late a predicted transition occurs compared with the true transition.

**Accuracy**  
The proportion of graded frames classified correctly. It is easy to understand but is not the
main ranking metric because it can hide fragmented spells and class imbalance.

## Submission terms

**`X` / abstention**  
The model declines to provide `H`, `A`, or `D`. Outside graded blocks this is harmless; inside a
graded block it counts as a miss for frame-level scoring.

**Graded frame**  
A frame included in the official score. The competition grades the two published half-blocks and
ignores the rest.

**Submission contract**  
The required output format: exactly `199319` rows with `frame,label`, frames `0..199318`, and
labels from `H`, `A`, `D`, or `X`.
